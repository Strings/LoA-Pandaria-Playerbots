# Treasures (T-093)

Hand-placed world treasures and the server-side placement validator (DESIGN.md, "World placement tool",
step 3, and "Treasures in nooks across every zone, with era-matched loot").

## Behaviour

- A treasure is any `gameobject` spawn whose template has `ScriptName = 'go_treasure'` (a chest, type 3, with
  a `data1` loot id and `gameobject_template_addon` gold). Templates live in the 909000 block
  (`docs/ID_RANGES.md`).
- Opening it rolls the template's loot for that character alone and puts it straight into the bags (no shared
  loot window, so friends can open the same chest at once). Full bags refuse the whole chest.
- The character gets a `characters.character_treasure` row. From then on the chest is hidden from that
  character only: `GameObject::IsNeverVisibleFor` asks `GameObjectHooks` (a small core hook in
  `game/Scripting/GameObjectHooks.h`), and this module answers from an in-memory set per online character.
  Other characters still see it, and it sparkles for everyone who has not opened it (per-viewer dynamic flags).
- A GM in GM mode still sees opened treasures (`Treasures.GmSeesLooted`).
- The first treasure a character opens shows a short popup (`Treasures.IntroOnFirstFind`).
- `world.treasure_spot` gives each spawn a label, a landmark note and the road point the validator walks from.
  A treasure spawn without a row still works.

## Placement validator

`.treasure validate <x> <y> <z> [map] [roadX roadY roadZ] [nudge]` (also over SOAP; in game the map defaults to
yours and the road point to where you stand) measures a candidate:

| Check | How |
|---|---|
| Ground | `Map::GetHeight` (terrain and vmap) snapped from 2 yd above; fails when the candidate is more than `MaxGroundOffset` off |
| Indoors | `Map::GetAreaInfo` (WMO root and group) and `Map::IsOutdoors` |
| Liquid | `Map::GetLiquidStatus`; deeper than 0.8 yd fails |
| Slope | heights 1 yd east, west, north and south |
| Line of sight | vmap ray from the road point at eye height (information only: hidden nooks are fine) |
| Reachability | `PathGenerator` (the code `.mmap path` uses) from an unspawned probe creature on the road point; a full path ending within 3 yd |
| Sky | five upward vmap rays (centre and 1.5 yd out); covered, partly covered or open (DESIGN.md, Flying rule). Open sky warns, or fails with `RequireCover` |
| Spacing | distance to the nearest other treasure spawn on the map |

`nudge` tries rings around a failing spot and reports the first that passes. The judging rules are pure code in
`TreasureRules.h`, unit-tested in `tests/treasures/`, so the offline placement tool can reuse them.

## GM commands (`.treasure`, permission 99000)

| Command | Does |
|---|---|
| `list [map]` | every treasure spawn with label and landmark |
| `go <id>` | teleport to a treasure |
| `spawn <entry> [roadX roadY roadZ]` | validate your position and place a permanent treasure there |
| `reset <id\|all> [character]` | forget opened treasures for a character (selected or yourself in game) |
| `looted [character]` | treasures a character has opened |
| `explain [id]` | spot, loot and, for each player near it, opened / visible / at client |
| `validate ...` | the validator above |
| `check <id\|all>` | re-validate placed treasures against their stored road points |
| `reload` | re-read `treasure_spot` and the config keys |

## Config

`Treasures.*` in `worldserver.conf.dist`. No timers: a treasure never respawns for a character.
